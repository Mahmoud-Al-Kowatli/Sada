# Sada AI — detection feature and research plan

## Research framing (from the proposal)
Detectors trained on ASVspoof 2019 collapse on modern TTS (García Martínez-Echevarría et al. 2026 on SONAR:
balanced accuracy ≈ 50 %, AUC ≈ 0.5; Müller et al. 2022: up to 1000 % degradation in the wild). Nobody has
published results on Levantine Arabic under telephone-like channel conditions. Sada's research question:

> Can Arabic adaptation and channel augmentation on a fixed architecture (B1 = wav2vec2 + linear head; B0 =
> LFCC-ResNet18 spectral baseline) reduce EER on a held-out Arabic test set with simulated channel transforms,
> and does the gain survive on an external set (SONAR) if accessible?

The experiment is reported whether or not the hypothesis holds. The platform does not depend on the outcome.

## Experiment matrix
| Code | Setup | Compares |
|---|---|---|
| B0 | LFCC(60) → ResNet-18, trained on ASVspoof 2019 LA | spectral baseline, runs on CPU |
| B1 | wav2vec2-base (frozen) → mean+std pooling → linear head, 2019 LA | value of pre-trained representation vs B0 |
| A1 | B1 + Arabic data in training | Arabic adaptation effect |
| A2 | B1 + channel augmentation (RawBoost-style: noise 20/10 dB SNR, 300–3400 Hz band-limit, 8 kHz resample, Opus) | augmentation effect |
| A3 | B1 + both | combined; the main hypothesis test is A3 vs B1 |
3 seeds each; EER, ROC-AUC, FPR at the fixed dev threshold; bootstrap 95 % CI; results per transform condition.
Threshold chosen on the Arabic dev split for FPR ≤ 5 %, frozen before touching the test split.

## Data
- ASVspoof 2019 LA (train/dev official) — English, 19 attacks, ODC-BY.
- Arabic_Audio_Deepfake (Hugging Face, DeepFake-Audio-Rangers) — Levantine, XTTS v2 / RVC v2, ≤ 3 s, 16 kHz, 19,561 rows, ODC-BY.
  Known gaps: one generator per type, no speaker ids → split by source file fingerprint, document it; label 0 = fake, 1 = real (flip before training!).
- Channel-transformed copies of the Arabic test split (generated by `scripts/augment.py` — to be written; keep seeds).
- SONAR (GitHub Jessegator/SONAR) — external test only, never for training or threshold tuning.
Compute: Kaggle / Google Colab notebooks; checkpoints saved every N steps; the service runs the frozen export.

## Service pipeline (`ai-service/app`)
`preprocess.py`: load (soundfile) → quality report → mono 16 kHz (linear interp; swap to librosa.resample when available) → peak normalize → 4 s windows, 3 s hop.
`features.py`: numpy LFCC — pre-emphasis 0.97, 25/10 ms Hamming frames, 512-FFT, 20 linear triangular filters, log, DCT-II → 20 + Δ + ΔΔ = 60 dims. **The training notebook must import this file** so features are identical at train and serve time.
`models/lfcc_resnet18.py`: `LfccResNet18(n_classes=2, width=16)` over (N, 1, 60, T).
`models/classifiers.py`: `StubClassifier` (deterministic pseudo-score, clearly labelled "not a detector") and `LfccResNet18Classifier(checkpoint_path)`; `build_classifier(name)`.
Config: `SADA_AI_CLASSIFIER=stub|lfcc_resnet18`, `SADA_AI_CHECKPOINT_PATH`, `SADA_AI_MODEL_VERSION`, `SADA_AI_THRESHOLD`.

## Checkpoint contract
`torch.save({"state_dict": model.state_dict(), "model_version": "lfcc-resnet18-B0-2026-xx", "threshold": 0.65,
"feature_config": {...}, "train_data": [...], "seed": 1}, path)`. The service reads `state_dict`; version and threshold come from env so the deployed values are explicit and audited.

## Explainability (planned)
Grad-CAM on the B0 spectral path over the LFCC image of the most suspicious window; for B1, attention/weight-based
saliency over time. Output: a time–frequency heatmap PNG + the window index, shown next to the audio player in the case screen. The heatmap supports the human decision; it is not a verdict.
